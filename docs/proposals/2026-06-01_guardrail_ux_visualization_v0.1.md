## 1. 한 줄 제안

정의 §6 가드레일(“정답·대본·합격 답변” 카피 금지)을 **사용자에게 보이는 마이크로카피·인터랙션 시스템 v1**으로 격상해, 평가에서 30%로 나온 *정책*을 *보이는 산출물*로 전환하고 AI 입시 startup 경쟁사와 직접 차별화한다.

## 2. 문제 정의

- **CEO 평가 (2026-06-01)**: 기능 80% / **정책 30%**, 기획 완결성 우려. 정책이 코드와 정의서 안에만 머물러 *사용자·평가위에게 보이지 않음*.
- **경쟁사 위협** (경쟁사 분석 v0.1 §3): AI 자소서·면접 답변 생성 startup 2건이 직접 경쟁권. 우리 wedge가 "AI가 정답을 생성"이 아니라 "AI가 진단·근거 제시·꼬리질문"임을 사용자가 첫 화면에서 *순식간에* 이해해야 함.
- **현 상태**: §6 가드레일은 `docs/002_definition_v.3.md` §6 + `prompt_v0.1.md`에만 박혀 있고, UI에는 1~2개 라벨 정도로만 표면화. 사용자가 처음 도착해서 "이게 답변 대본인가?" 오인할 여지 있음.

## 3. 제안 내용

### 3.1 마이크로카피 시스템 (5 토큰)

| 토큰 | 카피 | 적용 위치 |
|---|---|---|
| `NOT_ANSWER` | "정답이 아니라 *답변 방향*입니다" | /result 각 면접 질문 카드 상단 |
| `NOT_SCRIPT` | "외우는 대본이 아니라 *준비 지도*입니다" | /result 답변 방향 본문 상단 1회 |
| `NOT_PASS_GUARANTEE` | "합격을 보장하지 않습니다" | /landing 히어로 보조 카피 + /result 푸터 |
| `BASIS_SHOWN` | "이 진단은 학교생활기록부 §<섹션> 근거" | /result 진단 카드 각 항목 hover |
| `MINOR_GUARDED` | "미성년자 정보는 보호자 동의 후에만 처리됩니다" | /consent 게이트 + /submit 상단 |

> 5 토큰은 `packages/shared/src/guardrail_copy.ts` 단일 SSOT로 박고, 한 번 변경하면 전 라우트 일괄 반영.

### 3.2 인터랙션 (3건)

1. **근거 hover** — /result 진단 항목에 마우스 올리면 학교생활기록부 인용 구간이 사이드 패널에 표시. *AI가 어떤 근거로 이 진단을 냈는지* 가시화.
2. **"이건 정답?" 토글** — /result 상단에 작은 토글: "이게 정답 답변인가요?" → 클릭하면 "아니요. 정답은 학생 본인의 경험에서 나옵니다. 본 답변은 *방향과 근거*만 제시합니다." 모달 1회 노출.
3. **§6 가드레일 풋프린트** — 전 라우트 푸터에 작은 배지 1줄: "본 서비스는 §6 가드레일을 준수합니다 →" (클릭 시 가드레일 1page 설명 페이지로 이동)

### 3.3 적용 위치 (6 라우트 매핑)

| 라우트 | 적용 토큰·인터랙션 | 우선순위 |
|---|---|---|
| `/` (landing) | `NOT_PASS_GUARANTEE` 히어로 보조 + §6 배지 | P1 |
| `/submit` | `MINOR_GUARDED` 상단 | P1 |
| `/consent` | `MINOR_GUARDED` 게이트 | P1 |
| `/processing` | (변경 없음, 24h SLA 상태 그대로) | — |
| `/result` | `NOT_ANSWER` + `NOT_SCRIPT` + `BASIS_SHOWN` + "이건 정답?" 토글 | **P0** |
| `/parent` | `NOT_PASS_GUARANTEE` 푸터 (학부모용 톤 조정) | P2 |

**데이터 종속성** (2026-06-02 cross-check):
- `BASIS_SHOWN` 은 `prompt_v0.2` (`prompt_v0.1.md` 내 v0.2 패치, 2026-06-02 적용 완료)에 의존. 면접 질문(`interview_pack.questions[].evidence[]`)·진단 항목(`diagnosis_guide.criteria[].evidence[]`) 두 영역 모두 섹션 prefix(`세특-정보`·`창체-동아리` 등)를 포함한 evidence 배열을 강제. UI hover는 evidence 배열을 그대로 렌더링.
- 회귀 5건(golden case 01~05)이 신 schema로 재실행되어 통과해야 `/result` P0 적용 가능 — Phase D 머지 게이트.

## 4. 차별화 분석 (경쟁사 분석 v0.1 §3 연결)

| 경쟁사 유형 | 그들의 카피 톤 | 우리 wedge |
|---|---|---|
| AI 자소서·면접 답변 생성 startup A·B | "합격하는 답변", "정답 자소서", "베스트 답변" (추정) | **명시적으로 반대 톤** — "정답 아님·대본 아님·합격 보장 X" |
| 진학사·메가스터디 (콘텐츠) | 강사 브랜드·합격 데이터 | 우리는 데이터 두께 X, 대신 *진단의 투명성*으로 차별화 |

→ **첫 화면 3초 안에 사용자가 "여기는 다르다"를 인지**하는 것이 본 제안의 목표.

## 5. 기대 효과

1. **정책 가시화** — CEO 평가의 "정책 30%" 항목을 *보이는 UI 산출물*로 전환. 다음 평가 시 정량 평가 가능.
2. **사용자 신뢰** — "AI가 정답을 우긴다"는 오인 차단. NPS·재방문율 상승 가설.
3. **법적·평판 리스크 감소** — "합격 보장" 분쟁·미성년자 정보 분쟁의 1차 방어선.
4. **개발 차별화 자산** — `guardrail_copy.ts` SSOT는 향후 다른 트랙(writing-coach·초등)에서도 재사용 가능 (재사용 자산 룰 #2 충족).
