# 설계 — 학생 경험 마무리 배치 (자기답변·처리문구·결과 저장/공유, mock)

- 일자: 2026-06-25
- 대상: `apps/web` (입시 코치 프론트) — `feat/puds-adoption`(PUDS+인증+체인 통합) 위
- 방침: **프론트/mock으로 기능 완성**, 서버 저장·실제 공유는 직원 후속. mock은 교체 가능한 store로 격리.
- 상태: 설계 확정(브레인스토밍 승인) → 플랜 대기

## 1. 배경 / 목표
학생으로 서비스를 끝까지 써본 피드백에서 나온 핵심 격차 3종을 mock으로 메운다:
- **#27 자기답변** — 면접 "준비"인데 학생이 답을 직접 적을 곳이 없어 읽고 끝남.
- **#26 처리화면 문구** — `진척 13% · 클럭 시작=동의 완료 시점…` 같은 개발자 문구가 사용자에게 노출, 24h 대기가 막막.
- **결과 저장/공유** — 결과를 보관·재열람할 수단이 없음.

**비목표(직원 후속):** 서버 저장, 실제 링크 공유, 실 AI 결과. 본 작업은 프론트+localStorage mock.
**중복 금지:** #19 3역량·#17 PII·#22 면접 유형·#25 결과 프로필은 이미 머지됨 — 그 위에 얹기만.

## 2. 결정 사항 (확정)
| 항목 | 결정 |
|---|---|
| 자기답변 저장 | 질문별 localStorage 자동저장(mock store) |
| 처리화면 | 사용자 문구 + 기대치 관리(파이프라인 시각화 유지) |
| 결과 저장/공유 | PDF 인쇄 + 마이페이지 이력 실제 저장 + 링크 복사(clipboard mock) |
| §6 | 자기답변 = 학생 본인 메모(정답·대본 아님), 카피 불변 |

## 3. 자기답변 (#27)
- 면접 탭 각 질문 카드의 "꼬리질문 대비" 아래에 **"내 답변 써보기" 텍스트영역** 추가.
- 라벨/도움말로 §6 명시: **"AI 정답이 아니라, 답변 방향을 참고해 *스스로* 답해보는 칸입니다."**
- **자동 저장**(입력 디바운스 ~600ms) → 질문별 키로 localStorage. "저장됨 ✓" 표시(저장 시각/상태).
- 비로그인은 이미 RequireAuth로 차단되므로 로그인 사용자 전용. (저장 스코프: 현재 mock은 브라우저 단위 — 서버 연동 시 사용자/제출 단위.)

## 4. 처리화면 문구 (#26)
- `apps/web/app/processing/page.tsx`의 노출 문구만 교체(상태머신·4단계 파이프라인 시각화는 유지):
  - 개발자 줄(`진척 N% · 클럭 시작 = 동의 완료 시점, 클럭 종료 = 결과 노출`) **제거** → 현재 단계 사용자 설명(예: "생기부를 평가요소 기준으로 분석하고 있어요").
  - `24h SLA · 남은 시간 23:59` → **기대치 카피**: "보통 몇 분 안에 1차 결과가 나와요. 늦어도 24시간 안에 끝나고, 완료되면 알려드릴게요." (내부 약어 SLA/클럭 노출 금지.)
- §6 가드 라벨·단계명은 유지.

## 5. 결과 저장/공유
결과 페이지 하단(또는 헤더 액션)에 3개 액션:
- **PDF로 저장** — `window.print()` + **print CSS**(`@media print`로 사이드바·탭·버튼 숨기고 3종 결과 본문만 A4 가독 레이아웃). 백엔드 없이 실제 동작.
- **내 결과 저장** — 현재 결과(헤더 프로필 + 3종 요약)를 **result-store(localStorage)** 에 저장 → **마이페이지 "진단 이력"에 실제로 나타나고 "다시 보기"가 그 결과로 이동**. (지금 마이페이지 이력은 가짜 시드 → 실제 저장분으로 대체, 비어있으면 EmptyState.)
- **링크 복사** — `navigator.clipboard`로 결과 URL 복사 + "복사됨" 토스트. **단 실제 공유는 안 됨(백엔드 필요)** — 버튼 보조문구로 "베타: 링크 공유는 곧" 명시(가짜 기능으로 오해 방지, §정직).

## 6. 데이터 / 아키텍처
- **`lib/result-store.ts`** (mock, localStorage) — 교체 가능한 단일 표면:
  - `getAnswer(qid)` / `setAnswer(qid, text)` — 자기답변.
  - `saveDiagnosis(summary)` / `listDiagnoses()` / `getDiagnosis(id)` — 저장된 결과(마이페이지 이력).
  - 초기 시드 2건(완성된 느낌) + 사용자가 저장하면 추가.
- **마이페이지**는 `auth.listDiagnoses()` 대신(또는 병합) `result-store.listDiagnoses()`를 읽어 **실제 저장분** 표시. (employee swap 시 result-store만 서버 연동.)
- 자기답변/저장결과 모두 mock — **직원이 store 구현체만 교체**.

## 7. §6 / 접근성
- 자기답변 텍스트영역: AI가 채우지 않음(빈 칸), 라벨에 "정답 아님·스스로" 명시. placeholder도 §6 준수("예: 활동 → 배운 점 → 진로 연결 순으로 내 말로").
- print CSS: 본문 대비·줄간격 확보, 색 의존 최소(흑백 인쇄 가독).
- 토스트/저장 표시 aria-live.

## 8. 테스트
- **vitest**: `result-store`(getAnswer/setAnswer 라운드트립, saveDiagnosis→listDiagnoses, 시드).
- **수동 e2e**: 자기답변 입력→새로고침 후 유지 · 처리화면 문구 확인 · PDF 인쇄 미리보기 · 결과 저장→마이페이지 이력 등장→다시 보기 · 링크 복사 토스트.
- typecheck + build.

## 9. 범위 밖 (직원 후속)
서버 저장(사용자/제출 단위)·실제 링크 공유·실 AI 결과·이메일/카카오 완료 알림.

## 10. 리스크
- `auth.listDiagnoses`(AuthAdapter)와 `result-store.listDiagnoses` 중복 → 마이페이지는 result-store 단일 소스로, AuthAdapter의 것은 서버 히스토리용으로 분리(주석 명시).
- 링크 복사가 "가짜"로 오해될 위험 → 보조문구로 정직하게 표기.
- print CSS가 PUDS 토큰/다크 영향 받지 않도록 인쇄 전용 규칙 명시.
