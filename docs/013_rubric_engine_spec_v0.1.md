## 1. 엔진 목적 + "왜 단순 프롬프트가 아니라 유지보수형 도메인 자산인가"

### 1.1 목적

학생의 **구조화된 생기부 + 학생 메타(코호트·목표권역·전공계열)**를 입력받아, **학종 3역량 평가기준에 대한 진단 신호**를 **[정책] §3 대입-반영 항목(세특·정규 창체·행특)으로만 한정된 next-action 처방**으로 변환한다. 모든 처방은 (a) **생기부 원문 문장 인용**(증거링크), (b) **합법성 플래그**(화이트리스트 통과), (c) **불확실성 표기**, (d) **코호트·권역·전공 분기 근거**를 동반한다.

### 1.2 왜 "프롬프트 한 장"으로는 안 되는가 — 경쟁사 GPT 래퍼가 틀리는 지점

루브릭 엔진은 시스템 프롬프트 문자열이 아니라 **버전관리되는 도메인 데이터 자산 + 결정적(deterministic) 검증 게이트 + 골든 회귀**의 집합이다. 단순 GPT 래퍼가 구조적으로 틀리는 4개 지점이 바로 해자의 위치다.

| 단순 GPT 래퍼가 틀리는 지점 | 왜 프롬프트로 못 막는가 | 본 엔진의 방어 자산 |
|---|---|---|
| **코호트 혼선** (2027 구체제 vs 2028·2029 신체제에 같은 조언) | LLM은 "올해 기준"으로 평균화 → 5등급제·통합형 수능을 구체제 학생에게, 선택과목 전략을 신체제 학생에게 섞음. [R] §3.1 = "분기 없으면 구조적으로 틀린 조언" | §6 코호트 분기 규칙표 + 골든 "코호트 오분류 0건" 합격 기준([정책] §3.2) |
| **금지항목 처방** (수상·봉사·독서·자율동아리·소논문 권유) | LLM 사전학습 분포에 "스펙 쌓기" 일반 조언이 강하게 박혀 있어 프롬프트 한 줄로 억제 불안정. 무용+사교육 조장 비판([R] §3.3·§3.5) | §7 화이트리스트/블랙리스트 + 결정적 NG 스캐너([프롬프트] §4) + 골든 "금지항목 산출 0건" |
| **전공 권장과목 환각** (대학·학과별 상이한 권장과목을 단정) | 권장과목은 대학별 시행계획마다 다르고 매년 갱신([정책] §2.4) → 모델 메모리는 구식·평균값 → 허위정보 책임 리스크([R] §4.4 KILLER) | §5 데이터 레이어(하드코딩 금지·출처 인용) + "지망 대학 시행계획 직접 확인" 강제 병기 |
| **가드레일 드리프트** (모델/시즌 바뀌면 "진단→설계", "준비→대본"으로 미끄러짐) | 프롬프트만으로는 회귀 없이 위반을 탐지 못함 | 골든 회귀 5→확장 케이스 + NG 정규식 + EPO 검수 게이트(§9) |

핵심: **정확성·합법성을 "골든 회귀로 잠그는 것"**이 자산이다. 바이브온의 "일반론 보완추천"([R] §1-A 약점)은 회귀 없는 정적 생성이라 코호트·항목 정확성을 보증할 수 없다. 우리는 그 정확성을 테스트로 계약화한다.

### 1.3 엔진 = 3개 레이어

1. **데이터 레이어 (유지보수 자산):** 코호트 규칙표·권역 비중·전공 권장과목 출처·화이트리스트. 월 단위 정책 갱신 대상(§10). 코드 아님, 버전관리되는 JSON/표.
2. **추론 레이어 (LLM):** 데이터 레이어를 컨텍스트로 받아 생기부를 평가기준에 매핑하고 처방 후보를 생성. Claude 호출([프롬프트] §8 모델 가이드 승계).
3. **검증 레이어 (결정적):** 화이트리스트·NG 정규식·스키마·증거인용 충족·코호트 일관성을 코드로 검사. 불통과 시 폐기·재생성([프롬프트] §4 게이트 재사용).

## 2. 입력 — 구조화된 생기부 + 학생 메타 (스키마)

[스키마](student_profile_schema_v0.1.json)를 승계하되, 엔진은 **(a) 코호트·권역·전공 필수 필드**와 **(b) 구조화된 생기부 섹션**을 요구한다. ([v0.4] §4·[정책] §9 cascade 대상 — 본 엔진이 의존하는 확장 필드.)

### 2.1 입력 메타 (스키마 확장 — cascade 필요 필드)

| 필드 | 출처/상태 | 엔진 용도 |
|---|---|---|
| `cohort.admissionYear` | **신규 필수** ([v0.4] §4 승격, [정책] §1.1) | 코호트 체제 결정의 단일 진실원천(2024→구체제, 2025·2026→신체제) |
| `targetTrack` | [스키마] 기존 enum 5계열 | 전공 권장과목 매핑 분기(§5) |
| `targetRegion` | **신규** ([정책] §4) | 권역 분기(서울상위권/수도권/비수도권) |
| `currentStanding.{grade,semester,schoolType}` | [스키마] 기존 | 학교유형 보정([프롬프트] §2) |
| `targetUniversities[]` | [스키마] 기존(선택) | 권장과목 "시행계획 직접 확인" 안내 대상 |
| `record.maskingApplied=true` / `consent.*` | [스키마] 기존(P0) | 미충족 시 호출 차단([프롬프트] §3, [정책] §5) |

### 2.2 구조화된 생기부 (엔진 입력 정규형)

엔진은 마스킹 원문 텍스트를 **섹션 단위로 구조화**한 형태를 입력으로 받는다(증거링크의 앵커가 됨). 구조화는 호출 전 파서(NestJS) 책임이며, 본 스펙은 정규형을 정의한다.

```ts
// 엔진 입력: 구조화된 생기부
interface StructuredRecord {
  sections: RecordSection[];   // 생기부를 영역별로 쪼갠 단위
}

interface RecordSection {
  sectionId: string;           // 고유 ID. 증거링크 anchor (예: "sec-003")
  area: RecordArea;            // 주영역 (열거형, §7과 정합)
  subLabel?: string;           // 세부 (예: "정보", "수학", "동아리", "진로활동")
  text: string;                // 마스킹된 원문 문장(들) — 인용 출처
  gradeContext?: { grade: 1|2|3; semester: 1|2 };
}

// 생기부 주영역 — §7 화이트리스트와 1:1 정합
type RecordArea =
  | "semu"           // 세부능력 및 특기사항(세특)  ✅ 대입-반영(최우선)
  | "changche_auto"  // 창의적 체험활동 - 자율활동   ✅
  | "changche_career"// 창의적 체험활동 - 진로활동   ✅
  | "club_regular"   // 정규 동아리                  ✅
  | "haengtuk"       // 행동특성 및 종합의견(행특)    ✅(제한적)
  | "club_autonomous"// 자율동아리                   ❌ 미반영
  | "award"          // 수상경력                     ❌
  | "volunteer"      // 개인/외부 봉사실적           ❌
  | "reading"        // 독서활동                     ❌
  | "certificate"    // 자격증·인증                  ❌
  | "gifted"         // 영재/발명 실적               ❌
  | "other";         // 분류불가(처방 산출 금지)
```

> 입력 분류 자체는 ❌/⛔ 항목도 **보유**할 수 있다(학생 생기부에 실제로 존재하므로). 단 **처방(출력)은 ✅ 영역에서만** 생성된다(§7). ❌ 영역은 "진단 관찰의 참고"로만 읽고 next-action으로 전환하지 않는다.

## 3. 처리 — 학종 3역량 × 코호트규칙 × 전공 권장과목 매핑 로직

### 3.1 학종 3역량 (처방의 평가 축)

[프롬프트] §5의 5항목(학업·진로·공동체·인성·기타)을 본 엔진은 **학종 3역량**으로 집약해 처방 축으로 쓴다(인성·기타는 진단 가이드 측에서 유지, 처방은 3역량 중심).

| 역량 | 무엇을 보는가 | 처방이 향하는 ✅ 항목(주) |
|---|---|---|
| **학업역량** | 교과 성취·학습 시도·이수 깊이·탐구 | 세특(최우선) |
| **진로역량** | 진로 일관성·진로 탐색·교과-진로 연결 | 세특 · 창체-진로활동 · 정규 동아리 |
| **공동체역량** | 협력·역할·갈등해결 | 창체-자율활동 · 정규 동아리 · 행특(방향만) |

### 3.2 처리 파이프라인 (5스텝)

```
[1] 코호트 결정      cohort.admissionYear → regime(구체제|신체제)   (§6)
        ↓
[2] 컨텍스트 조립    regime + targetRegion + targetTrack로
                    데이터 레이어에서 (코호트규칙·권역비중·권장과목출처) 로드 (§5)
        ↓
[3] 진단 매핑       StructuredRecord.sections → 3역량별 강/약 신호
                    (각 신호는 sectionId 인용 1+ 필수)
        ↓
[4] 처방 후보 생성   약신호 → next-action 후보. **✅ 영역 타깃만**.
                    코호트·권역 무게 반영(신체제=세특 우선, §6)
        ↓
[5] 검증 게이트      화이트리스트 + 증거인용 + 코호트일관성 + NG정규식
                    (결정적). 불통과 → 폐기·재생성(최대 2회, [프롬프트]§4)
```

### 3.3 코호트규칙 적용(스텝 2·4)

[정책] §2를 처방 무게로 직접 적용한다.

- **신체제(2028·2029):** 5등급제 → 등급 변별력↓ → **세특·정성평가 우선**([정책] §2.2·§2.3). "수능 과목 선택" 조언 **금지**(선택과목 폐지·존재하지 않는 선택지, [정책] §2.1). 정시 지망자도 세특 처방 유효([정책] §4.3 tailwind).
- **구체제(2027):** 비치헤드 시즌 노드 — 신규 진단·인용 레이어 한정. 선택과목 조합 조언 유효하나 정시 컨설팅 비포함([v0.4] §9).

### 3.4 전공 권장과목 매핑(스텝 2·4)

[정책] §2.4를 따른다. 권장과목은 **데이터 레이어에서 출처와 함께 로드**, 처방에는 권장 이수 방향 + **"지망 대학 시행계획 직접 확인"** 안내를 항상 병기(§5·§8). 하드코딩·단정 금지([R] §4.4 KILLER).

## 4. 출력 — 대입-반영 항목으로만 한정된 next-action 처방

### 4.1 출력 계약(개요)

엔진은 **`prescription` 블록**을 산출한다. 이는 [프롬프트] v0.1 `improvements` 블록을 대체·승격한다. 모든 처방 아이템은 다음 4계약을 동시에 만족한다.

1. **합법성:** `legalFlag.area`가 ✅ 화이트리스트(§7)에 속함. ❌/⛔ 0건.
2. **증거인용:** `evidence[]`에 생기부 `sectionId` + 인용 문장 1+ (§8).
3. **불확실성:** `confidence` + 필요 시 `caveat`(예: 권장과목은 대학 직접 확인).
4. **분기 근거:** `cohortBasis`(체제·권역·전공으로 왜 이 처방인지) 명시.

### 4.2 처방 아이템 규칙(가드레일 인코딩)

- **주어 = "학생 본인", 시점 = "앞으로"** ([v0.4] §6.1, [정책] §3.2). 과거 기재분 첨삭·재작성 0건.
- **교사 기재영역(세특·행특) 문구 대필 0건.** 방향 제안만(예: "정보 수업 탐구를 진로와 잇는 추가 탐구를 스스로 해보면 좋겠습니다" ✅ / "세특에 '~'라고 적어달라고 요청하세요" ❌).

  track: TargetTrack;       // [스키마] enum 5계열
}

interface PrescriptionAction {
  actionId: string;
  competency: Competency;

## 6. 코호트 분기 로직 (의사결정 트리 + 규칙표)

### 6.1 의사결정 트리

```
입력: cohort.admissionYear (필수)
 │
 ├─ admissionYear == 2024  → regime = oldSystem (구체제·2027)
 │     · 9등급 / 선택형 수능 / 정성=mid
 │     · 비치헤드(시즌) 로직: 신규 진단·인용 레이어 한정, 정시 컨설팅 X
 │     · "선택과목 조합" 조언 허용
 │
 ├─ admissionYear ∈ {2025, 2026} → regime = newSystem (신체제·2028·2029)
 │     · 5등급 / 통합형 수능(선택과목 폐지) / 정성=high / 정시 정성평가=ON
 │     · 코어 로직: 세특(✅ 최우선) 우선 처방
 │     · "수능 과목 선택" 조언 **금지(존재하지 않는 선택지)**
 │     · 심화수학=수능 미출제이나 이공계 권장과목으로 별도 이수 분리 메시지
 │
 ├─ admissionYear >= 2027  → regime = newSystem  (+ 주니어 경계 확인 플래그)
 │     · 신체제 로직, 단 입시코치 vs 풀림 주니어 범위 확인([정책] §8 UNCERTAIN)
 │
 └─ admissionYear 누락/식별불가 → **에러: 처방 생성 차단**
       (코호트 미상은 구조적 오답 위험 → [정책] §3.2 "코호트 오분류 0건")
```

### 6.2 분기 규칙표 (처방 무게 결정)

| 분기 | 구체제(2027) | 신체제(2028·2029) | 검증 게이트 함의 |
|---|---|---|---|
| 수능 조언 | 선택과목 조합 허용(시즌 한정) | "과목 선택" 조언 산출 시 **불합격** | 신체제 출력에 선택과목 전략 키워드 → NG |
| 내신 조언 | 9등급 관리 | 5등급 전제 + "등급만으론 변별 안 됨" | 신체제 출력에 9등급 단정 → NG |
| 정성평가 무게 | 학종 지망 한정 | 전 지망자(정시 포함) 세특 처방 | — |
| 권장과목 | 기존 선택과목 체계 | 데이터 레이어 + 대학 확인 병기 | caveat 누락 시 불합격 |

## 7. 합법 액션 화이트리스트(✅) vs 금지리스트(❌/⛔) — 명세

[정책] §3.1을 엔진 운영 규칙으로 확정. **이 표가 검증 게이트와 골든 회귀의 합/불 판정 기준이다.**

| 분류 | `RecordArea` | 처방 산출 | 엔진 행동 규칙 |
|---|---|---|---|
| ✅ 반영(최우선) | `semu` (세특) | 허용 | 탐구·이수 깊이·성취 방향을 "학생 본인·앞으로". 문구 대필 금지 |
| ✅ 반영 | `changche_auto` (창체-자율) | 허용 | 정규 교육과정 내 활동만 |
| ✅ 반영 | `changche_career` (창체-진로) | 허용 | 진로 연결 방향 제안 |
| ✅ 반영 | `club_regular` (정규 동아리) | 허용 | **자율동아리와 구분 필수** |
| ✅ 반영(제한) | `haengtuk` (행특) | 허용(제한) | "학생 행동 방향"만. 교사 작성영역 문구 대필 금지 |
| ❌ 미반영 | `club_autonomous` (자율동아리) | **금지** | 권유 0건. 정규 동아리와 혼동 차단 |
| ❌ 미반영 | `award` (수상경력) | **금지** | 산출 0건 |
| ❌ 미반영 | `volunteer` (개인/외부 봉사) | **금지** | 산출 0건 |
| ❌ 미반영 | `reading` (독서활동) | **금지** | 산출 0건 |
| ❌ 미반영 | `certificate` (자격증·인증) | **금지** | 산출 0건 |
| ❌ 미반영 | `gifted` (영재/발명) | **금지** | 산출 0건 |
| ⛔ 미기재 | 소논문(R&E) | **금지** | **존재·권유 언급 자체 금지** |
| ⛔ 미기재 | 교외 수상 | **금지** | 언급·권유 금지 |
| ⛔ 미기재 | 사교육 유발 외부활동 | **금지** | 언급·권유 금지 |

**검증 게이트 합격 기준(결정적):**
- 모든 `action.targetArea` ∈ {✅ 5개}. 1건이라도 ❌/⛔ → **불합격(폐기·재생성)**.
- ⛔ 미기재 항목은 `description`·`evidence.quote` 어디에도 **문자열로도 등장 금지**(NG 정규식, [프롬프트] §4 통합).

근거: [R] §3.3 CONFIRMED. ❌/⛔ 권유 = 무용 + 사교육 조장 비판([R] §3.5).

## 8. 불확실성 · 증거인용 규약 (모든 처방이 생기부 문장 인용)

### 8.1 증거인용 규약(필수)

- **모든 `PrescriptionAction`은 `evidence[]` 1건 이상**을 갖는다(0건 = 불합격, [프롬프트] §6 자기검토 체크 7번 정합).
- 각 `EvidenceLink`는 `{ sectionId, area, quote }`를 모두 채운다. `quote`는 생기부 **원문 인용**(마스킹 유지, 변조·요약 금지)이며 처방 주장의 근거다.
- 인용 출처(`area`)는 ✅ 영역을 권장. ❌ 영역 문장은 "관찰의 참고"로만 인용 가능하되, 그 처방의 `targetArea`는 여전히 ✅여야 한다(즉 "수상 기록을 봤다"는 관찰은 가능하나, 처방은 세특 방향으로 돌린다).
- ⛔ 미기재 항목 문장은 인용 자체 금지.

### 8.2 불확실성 규약

| `confidence` | 사용 기준 | UI/카피 함의 |
|---|---|---|
| `high` | 생기부에 명확한 근거 + 코호트/항목 규칙 확정(CONFIRMED) | 권유형 단정 허용("~하면 더 또렷합니다") |
| `medium` | 근거 일부·해석 개입 | 관찰형으로 완화 |
| `low` | 권장과목 등 대학별 상이(UNCERTAIN) | **`caveat` 필수 + "대학 직접 확인" 병기** |

- **`PrescriptionOutput.globalCaveat`는 항상 채운다** — 최소 "지망 대학 모집요강(시행계획)을 직접 확인하세요"([정책] §2.4·§6.3, [R] §4.4 KILLER 책임 차단).
- 합격%·당락 단정 금지 — 근거 + 불확실성으로([R] §4.4 BUILDER).

## 9. 골든 회귀 테스트 설계 (기존 5케이스 확장)

### 9.1 기존 5케이스 한계와 확장 방향

[골든] v0.1 5케이스는 **5계열 × 4학교유형** 커버(§6.1 100%)이나 **코호트 분기가 없다**(전부 고2~고3 혼재, 입학연도 미지정). 본 엔진의 #1 리스크가 코호트 혼선이므로 **코호트 축을 신설**한다.

### 9.2 확장 케이스 매트릭스 (코호트 축 추가)

| 신규 ID | 코호트(입학연도/체제) | 권역 | 전공계열 | 검증 초점 |
|---|---|---|---|---|
| C-2027-A | 2024 / 구체제 | 수도권 | 이공 | 선택과목 조언 허용, 시즌 노드, 9등급 |
| C-2028-A | 2025 / 신체제 | 서울상위권 | 의예 | 5등급 전제 + 정시 정성평가 + 생명과학 권장(+대학확인 caveat) |
| C-2028-B | 2025 / 신체제 | 비수도권 | 인문 | 학종·교과 집중, 권장과목 UNCERTAIN→caveat |
| C-2029-A | 2026 / 신체제 | 서울상위권 | 이공 | 세특 우선, "수능 과목선택" 조언 산출 0건 |
| C-2029-B | 2026 / 신체제 | 수도권 | 예체능 | 권장과목 대학확인, 학교유형 보정 |
| (승계) 01~05 | 입학연도 부여 후 재실행 | — | — | 기존 5계열·4학교유형 커버 유지 |

### 9.3 합격 기준(결정적 게이트 — 회귀에 삽입)

[정책] §3.2 + 본 스펙:

1. **코호트 오분류 0건** — 신체제 케이스에 9등급/선택과목 조언, 구체제 케이스에 5등급 전제 = 즉시 불합격.
2. **금지항목 산출 0건** — `targetArea` ∈ ❌/⛔ 또는 ⛔ 미기재 문자열 등장 = 불합격(§7).
3. **증거인용 0건 결손** — 모든 처방 `evidence[] ≥ 1` + `quote` 비어있지 않음(§8).
4. **불확실성 누락 0건** — `confidence=low`인데 `caveat=null` = 불합격. `globalCaveat` 항상 존재.
5. **가드레일 위반 0건** — 주어≠학생·과거시점·문구대필·면접대본 = 불합격([프롬프트] §4 NG 정규식 재사용).

### 9.4 NG 셋 (코호트·동치오답 신규)

기존 [프롬프트] §4 NG 정규식에 **코호트·항목·동치오답** 패턴 추가:

```regex
# 코호트 NG (신체제 케이스 출력에 구체제 전제 — 오분류)
(선택과목|미적분|기하|확률과통계|과탐)\s*(조합|선택)\s*(전략|을\s*고민)   # 신체제 출력에 등장 시 NG
9\s*등급\s*(상대|기준|관리)                                              # 신체제 출력에 등장 시 NG

# 금지항목 NG (처방에 미반영/미기재 권유)
(수상|봉사|독서|자율\s*동아리|소논문|R&E|교외\s*수상)\s*(을|를)?\s*(준비|추가|챙기|쌓|권장|해\s*보)

# 동치오답 NG (자율동아리를 정규 동아리로 둔갑)
자율\s*동아리[^.\n]{0,30}(정규|교육과정\s*내)
```

### 9.5 동치오답(equivalence-trap) 검사 아이디어

골든 회귀가 "표면 문자열"만 막으면 모델이 우회 표현으로 빠져나간다. **의미적 동치오답 검사**를 추가한다(LLM judge + 결정적 보조):

- **항목 우회:** "교내 대회에 나가 보세요"(수상=`award` 우회) / "관심 책을 읽고 기록을 남겨보세요"(독서=`reading` 우회) / "뜻 맞는 친구와 동아리를 만들어"(자율동아리 우회) → 화이트리스트 우회로 판정 → 불합격.
- **코호트 우회:** 신체제인데 "수능 과목을 전략적으로 골라"를 "이수할 과목을 전략적으로 골라 수능에 대비"로 둔갑 → 코호트 우회.
- **대본 우회:** "이런 식으로 말하면 좋아요" 후 완성 문장 제시 → 면접 대본 우회([프롬프트] §4.2).
- 검사기는 처방 `description`을 (의도 분류 LLM judge) + (NG 정규식)으로 이중 검사하고, 둘 중 하나라도 우회 판정 시 폐기·재생성([프롬프트] §4 게이트 재사용).

## 10. 버전 · 정책 업데이트 운영 (월 단위 정책 반영 프로세스)

### 10.1 왜 월 단위인가

데이터 레이어(코호트 규칙·권역 비중·전공 권장과목)는 **대학별 시행계획·대교협 갱신·교육부 발표에 따라 변한다**([정책] §2.4·§10). 권장과목 단정은 책임 리스크([R] §4.4) → 자산을 코드와 분리해 **정기 갱신**한다. 이것이 "유지보수형 도메인 IP"(§1.2)의 운영 실체다.

### 10.2 버전 분리 (3계층 독립 버전)

| 버전 키 | 무엇 | 갱신 주기 | 출력에 기록 |
|---|---|---|---|
| `engineVersion` | 추론·검증 코드 | 기능 변경 시 | `PrescriptionOutput.engineVersion` |
| `policyVersion` | 데이터 레이어(코호트·권역·권장과목·화이트리스트) | **월 1회 + 긴급 핫픽스** | `PrescriptionOutput.policyVersion` |
| `promptVersion` | 시스템 프롬프트([프롬프트]) | 회귀 통과 시 | (호출 메타에 기록) |

→ 정책만 바뀌면 코드 배포 없이 데이터 레이어 + 골든 재실행으로 반영.

### 10.3 월간 운영 루프

```
[월초] 정책 스캔 (EPO)
  · 대교협 권역별 권장과목 갱신 / 대학별 시행계획 발표 / 교육부 공지 확인
  · [R]·[정책] §10 출처 재방문, UNCERTAIN→CONFIRMED 승격 후보 수집
        ↓
[검토] 변경 diff 작성 → CONFIRMED만 데이터 레이어 반영, UNCERTAIN은 caveat로
        ↓
[회귀] 골든 확장 케이스(§9) 전건 재실행 → 합격 기준 5종(§9.3) 통과 확인
        ↓
[승인] EPO 직접 검수·확정 → policyVersion 증가(예: 2026.06 → 2026.07)
        ↓
[배포] 데이터 레이어 교체. 코드 무변경 시 무중단. 변경이력 기록(§10.4)
        ↓
[감사] 출력의 policyVersion으로 "어느 정책버전으로 처방했는지" 역추적 가능
```

### 10.4 긴급 핫픽스 트리거(월 주기 외)

- 교육부/대교협이 코호트 규칙을 변경(예: 추가 개편) → **즉시 핫픽스 + 코호트 오분류 회귀 재실행**.
- 화이트리스트(✅/❌/⛔) 변경(대입 반영 항목 정책 변동) → **즉시 핫픽스**(법적·사교육 조장 리스크 직결, [정책] §7 P0).
- 권장과목 허위정보 신고 → 해당 항목 `certainty=UNCERTAIN` 강등 + caveat 강화.
