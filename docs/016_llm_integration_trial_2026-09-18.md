### 2.2 프롬프트 v0.4 — 문체 규칙

v0.3 → v0.4로 세 가지를 추가했다.

1. **§2 시스템 프롬프트에 `# 문체 — AI 투 금지` 11개 항.** 대구("A가 아니라 B다") 최대 1회, 평가 부사·최상급 금지, 격언조 마무리 금지, 3항 나열 금지, 줄표로 문장 잇기 금지, 화살표는 시간 순서에만, 강조는 수치·항목명에만, 근거 없는 면접 일반론 금지, 문장 평균 40자, 학생이 아니라 기록의 상태를 서술, 같은 끝맺음 4연속 금지.
2. **자기검토 체크리스트 11 → 12개.**
3. **§4.9 문체 NG 정규식 — 경고 게이트.** §4.1~4.8과 달리 하드 실패시키지 않는다. 재생성 1회 후에도 걸리면 통과시키고 `style_flag` + admin 알림만 남긴다.

규칙을 초안 카피에 돌려 검증했다. 초안은 WARN(대구 2, 과장부사 2, 평가형용사 1, 격언조 2, 일반론 1), 고친 카피는 PASS.

검증 과정에서 **규칙 자체의 오탐 3건**이 나와 §4.9에 회피 규칙을 추가했다.

- `evidence[]`는 전 규칙 제외. 생기부 원문 인용이라 모델의 문체가 아니다.
- 물음표로 끝나는 문장에는 과장 부사·평가 형용사 규칙 미적용. 면접 질문은 면접관의 구어다.
- 스캔 대상은 응답 JSON의 생성 문자열만. 골드 파일의 `notes:` 프런트매터와 입력은 제외.

## 3. 발견 사항

### 3.1 [보안 · 낮음] 인수인계 문서에 자격증명 평문 기재

노션 "풀림 라이팅코치" 페이지에 다음이 평문으로 있다.
**값 자체는 이 문서에 옮기지 않는다** — 리포지토리 이력에 남으면 되돌리는 데 rewrite 가 필요하다.

| 항목 | 비고 |
|---|---|
| **AWS 정적 액세스 키** (키 ID + 시크릿 + 계정번호 — 값은 노션 페이지 참조) | 만료 없는 IAM 장기 키. S3·RDS·Secrets Manager 접근 가능 |
| Anthropic API 키 | 같은 페이지에 두 번. 페이지에 "사용량 한도 미설정"이라고 적혀 있음 |
| `DEMO_ACCESS_TOKEN` (값은 노션 페이지 참조) | 영향도 낮음 |

**2026-09-18 확인: 해당 노션 페이지는 관련자만 열람 가능하다.** 외부 노출이 아니므로 긴급도는 낮다.
정리 자체는 남아 있다 — 키 로테이션 후 노션에서는 Secrets Manager 참조만 남기는 정리가 필요하다. 페이지의 "다음 단계"에 이미 "LLM 비용 한도·알림·비상 차단 기준 설정"이 있으므로 같이 처리할 수 있다.

**이번 실행은 그 Anthropic 키를 썼다.** 비용은 라이팅코치 계정에 붙었다. AWS 키는 사용하지 않았다.

### 3.2 [P1] PII 마스킹 모듈 버그 4건 — `packages/shared/src/pii.ts`

테스트 PDF에 `detectPii`/`redactPii`를 돌린 결과다. 25건 검출.

| 구분 | 내용 | 영향 |
|---|---|---|
| 누출 | 담임 교사명 3건이 안 잡힘. 규칙이 `담임: 이름` 인라인 형태만 보고 표 레이아웃 컬럼을 놓친다 | §6.3 위반 — 교사 실명이 모델로 전송됨 |
| 누출 | `070315-3******`가 RRN 규칙(`\d{6}-?[1-4]\d{6}`)에 안 걸림. 부분 마스킹된 주민번호의 **생년월일 앞 6자리가 그대로 남음** | §6.3 위반 |

이번 실행에서는 누출 2건을 손으로 막고 오탐 1건을 되돌린 뒤 전송했다. 과마스킹은 프로덕션이 실제로 보내는 모습을 보려고 그대로 뒀다.

### 3.3 [P2] §4 게이트 문서 구조 — 섹션 2개가 정규식 펜스를 갖고 있지 않다

`### 4.N` 헤딩 아래 ` ```regex ` 블록을 파싱하는 방식으로 게이트를 돌리면 **4.5와 4.7이 조용히 밀린다.** 두 섹션에 펜스가 없어서 파서가 4.6·4.8의 블록을 4.5·4.7 라벨로 가져간다. 라벨만 틀리고 패턴은 전부 실행되지만, 결과표를 읽는 사람이 오해한다.

- **4.5**는 의미 규칙이다(학교 유형 보정 누락 여부). 정규식으로 검사할 수 없고 사람이 봐야 한다.
- **4.7**은 기계 검증 가능하지만 TERM/VERB 조합 서술로 적혀 있다. 실제 구현은 `packages/shared/src/guardrails/unreflected-activities.ts`의 `UNREFLECTED_RECOMMENDATION_RE`에 있다. 게이트는 이 구현을 직접 불러야 한다.

### 3.4 [P1] 출력 스키마가 화면을 채우지 못한다

프로토타입 화면이 요구하는 것 중 셋이 `prompt_v0.1.md` 출력 스키마에 없다.

| 화면이 기대 | 실제 스키마 | 결과 |
|---|---|---|
| 근거에 생기부 원문 인용 | `evidence`는 `"세특-물리학"` 같은 섹션 문자열 배열 | 인용문 0건 |
| 적합도 4행 등급표(강함/적정/보완필요) | `fit_delta` 한 문단 | 표 렌더 불가 |
| 제안별 소요시간 · 왜 · 연결 질문 | `{title, description}` 두 필드 | 메타 없음 |

프로토타입은 이 자리를 가리지 않고 "출력 스키마에 없음" 안내로 표시한다. 화면을 유지하려면 스키마에 필드를 추가하고, 스키마를 유지하려면 화면을 줄여야 한다. 결정 필요.

### 3.5 [P1] 게이트를 통과한 출력의 내용 문제 4건

하드 게이트 8/8을 통과한 응답에서 나왔다. 정규식이 잡지 못하는 영역이다.

1. **§4-3 실질 위반.** 보완 제안 3번과 진로역량 `next_steps`가 GitHub 오픈소스 참여와 개발자 커뮤니티 활동을 권한다. 외부 활동은 생기부 미반영 항목이다. §4.7 정규식의 TERM은 독서·자율동아리·수상·봉사·영재·발명만 담고 있어 통과했다. 고3 2학기 학생에게 "앞으로 3개월간"을 붙인 점도 현실성이 없다.
2. **시점이 대학 진학 후로 넘어감.** 학업역량 `next_steps`가 "대학 세미나나 연구실 토론에서 제기하는 경험을 쌓으면"이다. §6.1은 시점을 "앞으로"로 규정하는데, 여기서 앞으로는 입시 전이어야 한다.
3. **학생 평가 + 슬로건.** "단순한 학업자에서 문제 정의자로 성장할 수 있을 것 같습니다", "개발자 커뮤니티의 일원이 되어 가는 중이라는 인상을 남길 수 있습니다". 문체 규칙 8·10번 위반인데 정규식에 안 걸린다.
4. **2인칭 "당신" 23회.** §6.3의 실명 호명 금지는 통과한다. 톤·언어 절에 인칭 조항이 없다.

### 3.6 [P2] 문서 간 모순 2건

- **1콜 vs 3콜.** `prompt_v0.1.md` §1은 "입력 1건 → 출력 3종 동시 생성", §2는 "시스템 1건 + 사용자 1건, 다중 턴 X"로 1콜을 규정한다. `apps/web/app/processing/page.tsx:36` 주석은 "opus 3콜(진단·처방·면접)"이다. 3콜이면 생기부를 세 번 보내 비용이 약 35% 오른다. 이번 실행은 SSOT를 따라 1콜로 했다. (`013` 문서의 "3콜→2콜"은 FE→BE HTTP 콜이라 무관하다.)
- **§7 캐싱 효과 수치가 틀렸다.** "시스템 + §5가 토큰의 대부분 → 입력 비용 60~80% 감소"라고 적혀 있다. 실측은 시스템 5,682 / 사용자 11,632 토큰이고, 입력 자체가 총비용의 약 21%다. 시스템 캐싱으로 줄어드는 몫은 **총비용의 약 5%**다.

### 3.7 [P3] §8 모델 선택 가이드가 낡았다

`claude-opus-4-7` / `claude-sonnet-4-6`으로 적혀 있다. 현행은 `claude-opus-5`(같은 $5/$25), `claude-sonnet-5`($2/$10 — 4-6의 $3/$15보다 저렴).

§8은 Haiku를 "사용 안 함(가드레일 신뢰도 부족 위험)"으로 배제한다. 이번 1건에서는 하드 게이트를 모두 지켰으나, §3.5의 4건이 게이트 밖에서 샜다. **표본 1건으로 §8을 뒤집기에는 이르다.**

## 4. LLM 실행 상세

### 4.1 구성

| 항목 | 값 |
|---|---|
| 모델 | `claude-haiku-4-5` (라이팅코치 `/api/score`와 동일) |
| 호출 수 | 1 (SSOT §1·§2) |
| 시스템 | §2 프롬프트 골격 + §5 매핑표, 두 블록 모두 캐시 대상 |
| thinking / effort | 미전송. Haiku 4.5는 adaptive thinking과 `output_config.effort`를 거부한다 |
| 면접 유형 | `lookupInterviewFormats` 결과 = record_based, passage_based |

Haiku 4.5는 `output_config.effort`에 400을 반환하고 thinking도 `budget_tokens` 방식이다. Opus 계열 파라미터를 그대로 보내면 실패한다.

### 4.2 실측 usage와 추정 정확도

| 구간 | 실측 토큰 | 사전 추정 | 오차 |
|---|---:|---|---|
| 시스템 (캐시 쓰기) | 5,682 | 3,368~4,324 | **31~69% 과소추정** |
| 입력 (생기부+템플릿) | 11,632 | 10,200~13,000 | 범위 안 |
| 출력 | 7,287 | 5,022~6,447 | **13~45% 과소추정** |

문자 수 기반 추정에서 한국어 토큰 비율을 낙관적으로 잡았다. 정확한 값이 필요하면 `count_tokens`(무료)로 재야 한다.

캐시는 정상 동작했다. 시스템이 5,682 토큰으로 Haiku 4.5의 최소 프리픽스 4,096을 넘겼다. 첫 호출이라 읽기는 0이고, 2회차부터 $0.1/MTok로 읽는다.

### 4.3 비용

**실측 $0.0552 (약 80원), 62.5초.**

같은 토큰으로 환산하면 Opus 5는 $0.276(사고 토큰 제외). 사전 추정 $0.32~0.42(사고 1배 포함)와 정합한다.

| 월 건수 | Haiku 4.5 | Opus 5 (환산) |
|---:|---:|---:|
| 500 | $28 | $138 |
| 2,000 | $110 | $552 |
| 10,000 | $552 | $2,760 |

생기부 분량에 대한 민감도는 낮다. 8쪽과 30쪽의 차이가 25% 수준이다. 출력 크기가 고정이라 그렇다.

### 4.4 검증 결과

구조 — 전부 통과.

```
✓ schema_version 0.2      ✓ 면접 질문 10건
✓ 진단 3역량(academic, career, community)   ✓ 보완 제안 3건
✓ record_based evidence ≥1 (누락 0)         ✓ 진단 highlight evidence ≥1 (누락 0)
```

§4 NG 게이트 — 라벨 밀림(§3.3)을 고치고 4.7은 저장소 구현을 써서 재실행한 결과다.

```

─ 4.5 케이스별(정규식 아님 — 사람 검토)      ✓ 4.6 진단 평가요소
✓ 4.7 미반영 항목(저장소 구현)              ✓ 4.8 면접 유형 대본화
△ 4.9 문체 — 경고 3건 (대구 1, "훨씬" 2)
```

면접 format 분포: record_based 9, passage_based 1.

### 4.5 출력 품질 관찰

Q3가 물리학 조도 측정과 인공지능 기초 모형 검증을 한 질문으로 묶었다. 손으로 쓴 진단에서 "교과 사이 연결이 끊겨 있다"고 약점으로 지목한 지점이다. 진단은 수치를 인용한다(물리학 96점, 무단결석 0일). 근거는 섹션 prefix를 지켰다.

문제는 §3.5에 정리했다.

## 5. 후속 작업 (2026-09-18 갱신)

### 5.1 결정된 것

**프롬프트 SSOT = `pullim-api/src/admissions/engine/system.ts`.** `prompt_v0.1.md` 는 설계 문서로 강등한다.
본 문서 §3.6 의 "1콜 vs 3콜"은 이것으로 닫힌다 — 프로덕션은 `engine/analyze.ts` 가
`diagnose → interviewPack → prescribe` 를 순차 호출하는 **3콜**이고, FE 주석이 맞았다.
(§4 의 1콜 실측은 `prompt_v0.1.md` 기준 실험이라 프로덕션 비용과 자릿수가 다르다 — §5.4.)

**적합도 표 축 = 기존 3역량(학업·진로·공동체) 유지.** 프로토타입의 4행 축(교과이수·지속성·
탐구깊이·주도성)은 채택하지 않는다 → `assessFit()` 무변경.

### 5.3 남은 것

1. **노션 값 정리** — 페이지 열람이 관련자로 제한돼 있어 긴급하지 않다. 정리 시 Secrets Manager 참조만 남긴다. (§3.1)
2. **골드 5건 회귀** — 스키마가 바뀌어 재실행이 필요하다. case-01·02 의 "탄탄"이 문체 게이트에 걸리는 건 EPO 판단.
3. **모델 ID** — `engine/models.ts` 가 `claude-opus-4-8`. 현행 Opus 5 로 올릴지 결정 필요.
4. **§4.9 오탐 판별** — 규칙·위반 사례를 *인용한* 텍스트에서 오탐. 모델 출력에서는 따옴표 안도 모델 문장이라 단순 제외 불가.
5. **택소노미 갭** — `submission-to-analysis-input` 의 6계열 → 5계열 매핑 손실(medical → natural). 이번에는 면접 유형용으로 원본을 따로 넘겨 우회했다.

### 5.4 비용 재추정 (프로덕션 기준)

§4.3 의 $0.0552 는 **Haiku 1콜** 실측이라 프로덕션과 다르다. 프로덕션은 `claude-opus-4-8`
**3콜** + adaptive thinking + `effort: high` 이고, 각 콜이 생기부 전문을 보낸다.
같은 토큰으로 환산하면 콜당 약 $0.28 → 3콜 약 $0.8/건(사고 토큰 별도). 스키마 확장으로
출력 토큰이 늘어 더 오른다. **확장 후 실측이 필요하다.**
