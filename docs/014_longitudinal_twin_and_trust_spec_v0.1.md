### 0.1 불변 가드레일 승계 (본 문서 전체에 적용)

[v0.4] §6 · [R] §5-5의 불변 가드레일을 그대로 따른다. 디지털 트윈은 다음을 **하지 않는다**:
- "진단(not 설계)": 트윈은 학생의 **실행 여부**를 추적할 뿐 생기부를 직접 고치지 않고, 교사 기재영역(세특·행특) 문구를 생성·대필하지 않는다([v0.4] §6.1).
- "면접 준비(not 대본)": 면접 노드 산출물은 트윈에 스냅샷으로 저장되되 완성 대본을 저장·재생하지 않는다([v0.4] §6.3).
- 처방·실행추적 항목은 **대입-반영 항목만**(✅세특/정규 창체/행특). 미반영(수상·자율동아리·외부봉사·독서·자격증)·미기재(소논문·교외수상·사교육유발활동·기관명) 항목은 트윈의 액션·진척 추적 대상에서 **구조적으로 배제**한다([v0.4] §6.2 · [R] §3.3).

## 1. 무엇을 만드는가 — 한 줄 정의

> **종단 디지털 트윈 = 한 학생의 생기부를 "학기별 스냅샷의 시계열"로 보유하고, 스냅샷 간 diff·처방 액션의 실행여부·재스코어링 추이를 증거인용과 불확실성과 함께 기록하는 1st-party 데이터 자산이며, 그 신뢰 토대는 "AI 미학습 + 즉시삭제 + 증거인용"이다.**

이 자산이 동시에 세 가지를 한다:
1. **루프 ③ 실행·추적**의 저장 기질([v0.4] §3.1) — 처방이 실행됐는지를 학기마다 증명.
2. **전환비용·1st-party 플라이휠**의 원천([v0.4] §5.3, §4) — 학기가 쌓일수록 떠나기 어렵고 처방이 정밀해진다.
3. **신뢰 해자**의 물리적 근거 — 바이브온 "비식별 데이터 AI 학습" 논란([R] §1-A, §4-4 KILLER)에 대해 "우리는 구조적으로 학습 불가"를 증명.

## 2. 종단 데이터 모델

### 2.1 핵심 개념 5종

| 개념 | 정의 | 비유 |
|---|---|---|
| **Twin** | 한 학생(가구)에 1:1로 묶인 종단 컨테이너 | 환자 차트 |
| **Snapshot** | 특정 학기에 업로드된 마스킹 생기부 + 그 시점 진단·처방 결과의 동결본 | 차트의 한 회차 검진 |
| **Diff** | 인접 두 Snapshot 간 변화(추가/수정/삭제된 기재, 점수 변동) | 검진 간 변화량 |
| **PrescribedAction** | 처방(루프 ②)이 발급한 합법 액션 1건. 학기 경과 후 실행여부 판정 대상 | 처방전 1줄 |
| **EvidenceCitation** | 모든 진단/처방 라인이 가리키는 생기부 원문 인용 + 위치 + 불확실성 | 차트 소견의 근거 인용 |

### 2.3 종단 흐름 (재스코어링 루프)

```
학기 t:  생기부 업로드 → Snapshot(t) 동결
           → 진단(루프①) → 각 라인에 EvidenceCitation + confidence
           → 처방(루프②, 해자#1 엔진) → PrescribedAction[] (대입-반영 항목만)
학기 t+1: 새 생기부 업로드 → Snapshot(t+1) 동결
           → SnapshotDiff(t→t+1) 산출 (섹션별 변화)
           → PrescribedAction 실행여부 판정:
               diff에서 해당 섹션 변화 탐지 → status=done + evidenceOfCompletion
               변화 없음 → not_done / 학생 self_report로 보완
           → 재스코어링: 동일 engineVersion으로 t+1 재진단 → scoreDelta 산출
           → 증명 리포트(루프④, 학부모용): "처방 N건 중 M건 실행, 역량 X 강화"
```

- **재스코어링 = 같은 엔진 버전으로 t와 t+1을 비교**해야 변화가 학생 실행 덕인지 엔진 변경 탓인지 분리된다(`engineVersion` 고정 비교). 엔진 업그레이드 시에는 과거 스냅샷을 신버전으로 **재계산한 별도 라인**을 두되, 학생-노출 추이는 동일버전 비교만 사용.

### 3.2 "즉시삭제" 정의 (UX 카피와 실제 SLA 정합)

마케팅 "즉시삭제"가 과장 표현이 되지 않도록 두 모드를 분리 정의한다:

| 모드 | 의미 | SLA | 대상 |
|---|---|---|---|
| **추론 후 즉시삭제(ephemeral)** | 일회성 진단 모드: 결과 생성 직후 입력 원문 파기, 트윈 미보유 | 추론 완료 즉시(분 단위) | 비치헤드(고3 시즌) 라이트 사용자, 트윈 옵트인 안 한 사용자 |
| **종단 보유(retained)** | 코어 구독자: 트윈에 학기 스냅샷 보유 | [보안] §5 보관기간(동의+12개월) | 코어(고1–2 연중) 구독자, 명시 동의 시 |

> **카피 가드:** "즉시삭제"는 ephemeral 모드 또는 사용자 삭제요청(48h 이내, [보안] §5.2) 두 경우에만 사용. 종단 보유 사용자에게는 "동의 기간 동안만 안전 보유, 언제든 즉시 삭제 가능"으로 표현. 과장 카피는 [v0.4] §6.1 헤드윈드(신뢰 역풍) 위반.

### 3.3 학습 불가의 구조적 보증 (검증 가능)

- **T2→ML 경로 부재:** T2 데이터는 추론(Anthropic API) 외 어떤 파이프라인에도 라우팅되지 않는다. 운영 통계는 [보안] §2 T4(비식별 지표)만 사용.
- **외부 추론 학습 차단:** Anthropic API의 학습 불사용 설정 + 위탁처리계약([보안] §10)에 "위탁데이터 모델 학습 금지" 조항 명문화.
- **검증 게이트(8/1 출시 전, [보안] §9에 추가):**
  - [ ] T2 데이터가 ML/학습/파인튜닝 잡에 유입되는 경로 0건(코드·인프라 전수)
  - [ ] Anthropic 호출 페이로드에 no-train 옵션 적용 자동 테스트 통과
  - [ ] "비식별 후 학습" 류 내부 데이터 사용 정책 부재 명문화(있으면 별도 동의 필요, [R] §3.4)

## 4. 증거인용 메커니즘 + 불확실성 정량화

### 4.1 증거인용 (golden v0.2 evidence 컬럼 연계)

- **원칙:** 모든 진단 라인·처방 라인·면접 노드는 EvidenceCitation 1건 이상을 반드시 가진다(인용 없는 주장 = 회귀 실패). 이는 [R] §4-4 BUILDER "근거+불확실성"을 데이터 모델로 강제한 것.
- **golden 연계:** 현 golden 케이스 진단 가이드의 "근거 인용 (학교생활기록부)" 컬럼(`docs/golden/case-*.md` 기대출력 ②)을 EvidenceCitation 엔티티 규격으로 정본화한다. golden v0.2는 각 진단/처방 라인에 `quote`+`sourceSection`+`confidence`를 **필수 컬럼**으로 추가한다.
- **회귀 게이트(해자 #1 골든 회귀에 추가):**
  - [ ] 진단/처방/면접 라인 중 EvidenceCitation 0건인 라인 = 0
  - [ ] EvidenceCitation의 `quote`가 입력 생기부에 실재(환각 인용 탐지) = 위반 0
  - [ ] 인용 섹션이 대입-반영 5섹션 외 = 위반 0 (§0.1)

### 4.2 불확실성 정량화 (단정 금지)

[R] §4-4 KILLER("합격% 단정"은 신뢰 파괴) → 트윈은 합격가능성을 단정하지 않고 **신뢰도 라벨**을 동반한다.

| confidence | 의미 | 트리거 | 노출 카피 예 |
|---|---|---|---|
| `high` | 직접 인용이 명확히 뒷받침 | 명시적 기재 + 충분 분량 | "세특에 기록이 분명합니다" |
| `medium` | 부분 근거 + 일부 추론 | 단편 기재 / 간접 신호 | "기록 일부로 보아 ~로 보입니다(확인 필요)" |
| `low` | 근거 빈약 / 추론 비중 큼 | 기재 거의 없음 | "근거가 부족해 단정하기 어렵습니다" |

- **합격가능성 단정 금지:** 트윈은 진학사식 합격%를 산출·저장하지 않는다([v0.4] §8·[R] §5-6 — 인용·해석 레이어). 산출 시 회귀 실패.
- **재스코어링 추이에도 불확실성 표기:** scoreDelta는 "강함→매우강함" 같은 단정 대신 "근거가 보강됨(medium→high)" 식 변화로 표현.

## 5. 전환비용 + 1st-party 플라이휠 설계

[v0.4] §5.3 경제 해자를 메커니즘으로 명시한다.

### 5.1 전환비용 (학기가 쌓일수록 떠나기 어렵다)

| 누적 자산 | 떠날 때 잃는 것 | 강화 메커니즘 |
|---|---|---|
| Snapshot 시계열 | 다년치 생기부 변화 기록 | 경쟁사는 1회성 read-only라 종단 이력 자체가 없음([R] §5-2) |
| PrescribedAction 실행이력 | "무엇을 처방받아 실행했는가"의 증명 | 증명 리포트(루프④)가 학부모 결제 정당화 근거 |
| 증명 리포트 누적 | 학부모에게 보여줄 진척 서사 | 결제자(학부모) 락인 — 결제자≠사용자 이중레이어([v0.4] §2) |

> **전환비용의 윤리적 상한:** 락인은 데이터 인질이 되어선 안 된다. 사용자 export(본인 데이터 다운로드)·삭제권은 항상 보장([보안] §5.2). 전환비용은 "데이터를 못 가져가게"가 아니라 "여기서 쌓은 종단 처방-증명 서사가 가치"여야 한다.

### 5.2 1st-party 플라이휠 (처방이 정밀해진다)

```
스냅샷 쌓임 → diff로 "어떤 처방이 실제 실행/효과로 이어졌나"의 1st-party 신호
   → 해자#1 루브릭 엔진의 골든셋·휴리스틱 개선(집계·비식별 T4만)
   → 처방 정밀도↑ → 증명 효과↑ → 구독 유지↑ → 스냅샷 더 쌓임
```

- **플라이휠 ≠ 학습:** 이 개선은 **개별 T2 학습이 아니라 비식별 집계 신호(T4)로 도메인 IP를 수동 개선**하는 것이다(§3.3 무학습과 충돌 없음). "어떤 처방 유형이 실행률이 높은가" 같은 집계 통계만 사용.
- **plausibility 가드:** 처방→실행→점수변화의 인과를 단정하지 않는다(상관 신호로만 엔진 튜닝 우선순위 결정).

## 6. 민감정보·미성년 동의 플로우 (트윈 보유 추가 동의)

### 6.1 동의 레이어 (기존 4종 + 종단/AI 추가)

| 동의 | 주체 | 기존? | 트윈 관련성 |
|---|---|---|---|

### 6.2 연령·법정대리인 게이트

- **만 14세 미만:** 법정대리인 동의 필수, 동의확인용 보호자정보는 확인 후 파기([R] §3.4). (타깃 고1–3 대부분은 14세 이상 → 본인 동의 가능, 부담↓.)
- **[회원]과의 정합 주의:** [회원]은 `isMinor`를 "만 19세 미만"으로 정의(보호자 동의 운영 기준). [R]/PIPA 법정 게이트는 "만 14세 미만". → **두 기준 병기 운영:** 14세 미만=법정 필수 게이트(P0 차단), 14~19세 미성년=서비스 정책상 보호자 동의 운영. (이 이중 기준은 §8 미해결로 CEO/법무 확정 필요.)
- **직접 업로드 강제:** 학생 본인 또는 법정대리인만 생기부 업로드(학교→제3자 제공 우회 금지, 교육기본법 §23의3, [R] §3.4).

### 6.3 트윈 활성화 조건 (앱 레벨 강제)

종단 트윈 보유(retained)는 [회원] 미성년 활성화 4조건 + 다음 2조건을 **모두** 충족해야 한다:
5. `longitudinal_retention` granted=true
6. `ai_processing` granted=true
→ 미충족 시 ephemeral 모드(트윈 미생성)로만 동작. 동의 철회 시 트윈 전체 즉시 삭제([보안] §5.3).

## 8. 미해결 질문 (CEO/법무 확정용)

1. **`isMinor` 이중 기준(14세 vs 19세)** — 법정 게이트(14세 미만, [R] §3.4)와 [회원] 운영 기준(19세 미만) 병기 운영안을 법무가 확정해야 한다(§6.2). 종단 보유 동의를 19세 미만 전원에 보호자 동의로 받을지 여부.
2. **종단 보관기간 vs 학종 사이클** — [보안] §5는 "동의+12개월". 그러나 종단 트윈의 가치는 고1→고3 다년(최대 36개월)이다. 12개월 갱신 동의 반복으로 갈지, 종단 전용 보관기간(예: 졸업+α)을 신설할지 확정 필요(법무·[보안] v0.2 갱신 대상).
3. **사람검수(human_review) 운영 여부** — PrescribedAction.verificationMethod·증명 리포트 품질 게이트가 사람검수 가능 여부에 따라 달라진다([v0.4] 미해결 #3 연동).
4. **재스코어링 케이던스** — diff·재스코어링을 학기 1회로 고정할지, 월 단위 추적까지 갈지(코어 SLA "학기별 추적 케이던스" 구체화, [v0.4] §3.3·미해결 #6).
5. **OS 연동 착수 마일스톤(#3)** — §7.3 "코어 중기"의 구체 시점·우선순위([v0.4] 미해결 #5).
6. **ephemeral vs retained 기본값** — 비치헤드 고3 라이트 사용자의 기본을 ephemeral로 둘지, 트윈 옵트인을 얼마나 강하게 권유할지(전환 깔때기 vs 신뢰 카피 균형).
7. **"즉시삭제" 카피 법무 검토** — §3.2 모드별 카피가 표시광고법·과장표현 리스크가 없는지(retained 사용자에게 "즉시삭제" 단독 사용 금지 규칙 확정).
