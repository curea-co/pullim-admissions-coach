- **(B) [권장과목 데이터 레이어 운영주체·주기] 013 §5.2·§10.** 013은 전공 권장과목·코호트 규칙·권역 비중·화이트리스트를 "코드와 분리된 버전관리 데이터 레이어"로 두고 **월 1회+긴급 핫픽스로 EPO가 직접 스캔·갱신**(§10.3 루프)하도록 설계. 이는 [정책]§2.4(하드코딩 금지)·§8과 정합하나, **운영주체·월간 공수·핫픽스 책임을 누가 지속 부담하는지**는 미확정(EPO 단독? 별도 운영 인력?) → **D13(권장과목/정책 데이터 레이어 운영주체·케이던스 확정)**.
- **(C) [3역량 vs 5항목 설계 확정] 013 §3.1.** 처방 축을 3역량으로 집약하고 인성·기타는 진단 가이드(5항목) 유지 — 출력 모순은 없으나(§2 (a)), "진단=5/처방=3"의 **이원 축을 정본 설계로 확정**할지(또는 진단도 3역량으로 통일/처방도 5항목 유지) CEO/EPO 판단 필요. UI·리포트 일관성에 영향 → **D14(진단 5항목 / 처방 3역량 이원 축 확정)**.
- **(D) [LLM-judge 의존도] 013 §9.5 동치오답 검사.** 표면 NG 정규식만으로는 모델이 우회 표현으로 화이트리스트/코호트/대본 가드를 빠져나가므로, **LLM judge(의도 분류) + 결정적 NG 정규식 이중 검사**를 도입. 이는 가드레일 강건성을 높이나 (i) 골든 회귀 합/불 판정이 **비결정적 LLM judge에 부분 의존**, (ii) judge 자체 비용·신뢰도·회귀 검증 부담을 신설한다([프롬프트]§9-4가 이미 "LLM judge 또는 인간 검수"를 열어둔 것과 정합하나 자동 게이트 의존도는 상승). → **D15(골든 게이트의 LLM-judge 의존 허용범위·judge 자체 회귀/인간 fallback 정책)**.
