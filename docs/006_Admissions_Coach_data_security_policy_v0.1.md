## 1. 목적·적용 범위

본 정책은 Pullim Admissions Coach가 처리하는 모든 데이터의 분류·암호화·보관·삭제·접근 통제 기준을 정의한다. 정의 v0.3 §6.3을 운영 가능한 사양으로 풀어낸 문서이며, 한국 개인정보보호법(PIPA)·청소년보호법·청소년 관련 ICT 가이드라인과 정합한다.

적용 범위: web/api/admin 3 앱, RDS·S3·Redis·SES·로그, 모든 dev/staging/prod 환경.

## 2. 데이터 분류 (4 Tier)

| Tier | 분류 | 예시 | 처리 원칙 |
|---:|---|---|---|
| **T1** | 식별 PII | 학생 성명·학교명·생년월일·전화·주소·교사명·법정대리인 정보 | **평문 저장 금지.** 입력 단계에서 마스킹·익명 식별자(UUID)로 치환. 원본 필요 시 KMS 봉투 암호화(Phase E) |
| **T2** | 미성년자 민감 콘텐츠 | 생기부 원문·파싱 텍스트·면접 준비 팩·진단 가이드·활동 보완안 결과물 | **봉투 암호화 보관**(Phase E). 보호자 동의 + 본인 동의 둘 다 확인된 시점부터만 저장. 보관 만료 도래 시 자동 삭제 |
| **T3** | 동의·감사 로그 | 약관·개인정보·법정대리인 동의 이벤트, 데이터 접근 로그, 운영자 행위 로그 | **무결성 우선** (append-only, 변조 방지). PIPA §29 권고 보존(3년)까지 보존, 그 후 안전 폐기 |
| **T4** | 운영·통계 데이터 | 학부 계열 통계, 학교 유형 분포, 비식별 사용 지표 | 표준 보호. 비식별 처리 후 운영·분석에 사용 가능 |

**식별 가능성 판단:** T2의 "마스킹된" 생기부도 결합 시 학생을 재식별할 위험이 있으므로 **T2 = 미성년자 민감 콘텐츠로 일관 취급**한다. "마스킹했으니 보호 수준을 낮춰도 된다"는 판단 금지.

## 3. 암호화 정책

### 3.1 전송 (in transit)

- 모든 외부 트래픽: TLS 1.2+ (ALB에서 종료). HTTP는 영구 리다이렉트.
- VPC 내부 통신(NestJS↔RDS, NestJS↔Redis, ECS Service Connect): 기본 TLS. 미지원 시 보안 그룹으로 격리.
- 외부 API 호출(Anthropic, Toss, SES, 알림톡): TLS 검증 필수.

### 3.2 저장 (at rest)

| 자산 | 표준 암호화 (Phase 0~D) | 강화 암호화 (Phase E) |
|---|---|---|
| RDS Postgres | RDS 기본 암호화(AWS-managed key) ON | 고객 관리 KMS 키로 전환, PII 컬럼 pgcrypto |
| S3 (생기부 PDF, 결과물) | SSE-S3 기본 ON, 퍼블릭 차단 | SSE-KMS + **T2는 application-level 봉투 암호화 추가** |
| EBS (ECS 작업 디렉토리) | 기본 암호화 ON | 동일 |
| Redis (BullMQ 잡 페이로드) | TLS in transit + Redis AUTH | T2 페이로드는 ID 참조만 저장(원문 미저장) |
| CloudWatch Logs | 기본 암호화 | 로그 마스킹 필터 적용 |
| Backups (RDS 스냅샷, S3 버전) | 기본 암호화 | 동일 |

### 3.3 애플리케이션 봉투 암호화 (T2 전용, Phase E 시행)

- 데이터 키(DEK)는 매 레코드/매 파일 생성, KMS 마스터 키(CMK)로 wrap.
- 평문 데이터는 메모리 외 어디에도 잔존 금지(임시 파일·디스크 캐시 금지).
- 키 회전: CMK는 자동 회전(연 1회), DEK는 객체 단위.

### 3.4 키 관리 분리

- 개발·스테이징·프로덕션 각각 독립 KMS 키.
- 운영자가 평문 데이터를 직접 조회할 수 없도록 키 정책 분리(개발자는 dev key만, 운영 SRE 일부만 prod key).

## 4. 단계적 시행 (Phased Rollout) — **컴플라이언스 핵심**

> **원칙: 실제 미성년자 학생부 데이터는 Phase E 완료(KMS·동의·삭제 정책 모두 가동) 이후에만 수집한다.** Phase 0~D 동안에는 합성·가명·내부 검수 데이터만 사용.

| Phase | 데이터 유형 | 암호화 상태 | 비고 |
|---|---|---|---|
| 0 | 인프라만, 사용자 데이터 없음 | 기본 암호화 ON | 정책 문서 v1 닫힘 |
| A | 박준호 mock(합성) | 기본 암호화 | 실 PII 없음 |
| B | 합성 입력 + 폼 검증 데이터 | 기본 암호화 | 실 PII 없음 |
| C | 합성 + 골드 데이터(가명) | 기본 암호화 | 골드 데이터는 EPO가 만든 가명처리분 |
| D | 골드 5건 + 베타 검수(가명) | 기본 암호화 | 베타 30건/주는 *가명처리* + EPO 입회 검수 |
| **E** | **실 미성년자 데이터 수집 시작** | **KMS 봉투 암호화 + 동의·삭제 가동** | **8/1 출시 = 본 정책 v1 모든 항목 시행** |

이 staging이 정의 §6.3과 정합되는 이유: 보호자 동의 채널과 삭제 cron이 가동되기 전에 실 미성년자 데이터를 받지 않으므로, 강화 암호화 시점이 데이터 수집 시점과 일치한다.

## 5. 보관·삭제 정책

### 5.1 보관 기간

| 데이터 | 기본 보관 | 근거 |
|---|---|---|
| 학생 입력(T1·T2) | 동의 시점 + **12개월** | 학종 1 사이클 + 합격 확인 여유 |
| 결과물(T2) | 동의 시점 + **12개월** | 동일 |
| 동의·감사 로그(T3) | **3년** | PIPA §29 권고 |
| 결제 데이터(T1, Phase E) | 5년 | 전자상거래법 |
| 운영 통계(T4 비식별) | 무기한 | 비식별 처리 완료 시 |

### 5.2 삭제 절차

- 보관 만료 도래 시 NestJS `@Cron` 스케줄러가 매일 1회 만료 레코드 스캔 → 30일 grace period → 영구 삭제.
- 사용자 즉시 삭제 요청(PIPA 정정·삭제권): 48시간 이내 처리, 삭제 완료 통지.
- 삭제는 **물리 삭제** (soft delete 후 cron으로 hard delete). 미성년자 데이터는 영구 보존 금지.
- 백업·스냅샷 내 데이터도 보관 정책에 포함(롤링 폐기).

### 5.3 동의 철회

- 학생 또는 법정대리인이 동의 철회 시: 처리 중인 잡은 중단, 저장된 T1·T2 즉시 삭제, T3 동의 철회 이벤트만 보존.

## 6. 접근 통제

### 6.1 인적 접근

- RDS 직접 접근은 **Bastion 경유 + IAM 인증** 또는 **SSM Session Manager**. SSH 키 공유 금지.
- 운영자 DB 접근 시 접근 사유·티켓 번호 로깅(T3).
- M3 베타 이후 **4-eyes 원칙**: 실 PII 조회는 EPO + SRE 두 명 동시 승인.
- 권한 최소화: 개발자는 dev/staging만, 프로덕션은 SRE 소수.

### 6.2 시스템 접근

- ECS 작업 역할(IAM)은 필요 최소 권한만(S3 버킷 단일, KMS 키 단일).
- Anthropic·Toss·SES 등 외부 API 키는 AWS Secrets Manager 또는 SSM Parameter Store(SecureString). 코드/저장소 평문 금지.
- GitHub Actions OIDC 페더레이션(장기 키 금지).

### 6.3 네트워크 접근

- RDS·Redis는 프라이빗 서브넷, 보안 그룹으로 NestJS 작업 역할에서만 접근.
- WAF 룰:
  - 표준 Managed Rules (OWASP Top 10)
  - `/api/auth/*`: 분당 5회 이상 실패 시 차단 (브루트포스)
  - `/api/submit`: 사용자당 분당 3회 (남용 방지)
  - `/api/consent`: 사용자당 분당 5회
  - 옵션: 한국 외 지역 차단 (마케팅 정책에 따라)

## 7. 모니터링·사고 대응

- 로그 수집: CloudWatch Logs (앱·ECS·ALB·WAF·RDS·S3 액세스 로그) → Phase E 본격 가동.
- 이상 탐지(Phase E):
  - 단일 IP 다량 제출, 미성년자 마스킹 우회 시도, T2 데이터 외부 송출 패턴.
  - WAF 차단 이벤트 임계 초과 시 SRE 알림.
- **PIPA §34 사고 통지 의무**: 개인정보 유출 시 72시간 이내 한국인터넷진흥원(KISA) 통지 + 정보주체 통지.
- 사고 대응 절차(Phase E 산출물 별도 문서): 탐지→봉쇄→통지→복구→사후분석.

## 8. 미성년자 특별 가드 (정의 §6.3)

1. **법정대리인 동의**: 미성년자(만 14세 미만 포함)는 본인 동의 + 법정대리인 동의 둘 다 획득. 채널은 SES 메일 + 카카오 알림톡/SMS(Phase E 결정).
2. **마스킹 강제**: 입력 단계에서 식별정보 마스킹을 기본값으로 강제 (`student_profile_schema_v0.1.json`의 `record.maskingApplied: true` const).
   - **마스킹 자동 검출(#17, Phase B):** 입력 단계에서 `packages/shared/src/pii.ts`가 전화·주민번호·이메일·학교명을 하드 차단, 이름·교사·주소·생년월일을 경고+2차 확인. Phase C에서 동일 함수를 NestJS pipe로 서버 재검증.
3. **목적 외 이용 금지**: T2 데이터는 §4 출력 3종 생성 외 사용 금지. AI 학습 데이터 제공 금지(Anthropic API 호출 시 학습 불사용 옵션 확인).
4. **자녀 데이터의 학부모 접근 범위**: 학부모 리포트(§4-3)는 학습 진행 요약만 노출, 생기부 원문·결과물 전문은 노출하지 않음(학생-학부모 권한 분리).
5. **삭제권**: 학생 또는 법정대리인 일방의 요청만으로 삭제 가능.
